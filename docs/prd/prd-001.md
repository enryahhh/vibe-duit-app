# PRD-001: Multi-Account & E-Wallet Financial Record-Keeping

**Version:** 1.0  
**Status:** Draft  
**Owner:** Product Manager  
**Priority:** P0 (Must-have)

---

## 1. Objective

Enable users to consolidate all their financial accounts (bank accounts, e-wallets, cash) in one place, and accurately record, categorize, and review their income and expenses. This forms the foundational data layer for all subsequent goal and analysis features.

## 2. User Stories

- As a user, I want to link my bank accounts and e-wallets so that all my balances and transactions are visible in a single view.
- As a user, I want to manually add an offline cash account so I can track cash spending.
- As a user, I want to log a new income or expense with a category, amount, account, and date so my records stay complete.
- As a user, I want to see my current net worth (total assets minus liabilities) across all accounts.
- As a user, I want to view a history of all transactions filtered by account, date, or category.

## 3. Functional Requirements

### 3.1 Account Management

- **FR1.1:** System shall allow users to add accounts with the following types: Bank Account, E-Wallet (e.g., GoPay, OVO, PayPal), Cash, Investment Account (basic balance tracking only for now), and Credit Card (liability).
- **FR1.2:** For each account, the user shall provide: Account Name, Account Type, Currency, Current Balance (manual entry), and optionally institution name and account number mask.
- **FR1.3:** System shall support manual balance updates for unlinked accounts and display a last-updated timestamp.
- **FR1.4:** (Future) Optional bank/e-wallet API integration for automatic balance and transaction syncing – out of scope for V1.

### 3.2 Transaction Recording – Input Form

- **FR1.5:** The system must expose a **Transaction Input Form** with the following fields (see Section 4).
- **FR1.6:** After submitting, the system shall:
    - Deduct the amount from the source account’s balance for an expense.
    - Add the amount to the destination account’s balance for an income (if an account is the target).
    - For transfers between user’s own accounts, debit one and credit the other with a transfer category.

### 3.3 Transaction Categorization

- **FR1.7:** System shall provide a default set of categories (Food, Transport, Shopping, Bills, Salary, Investment, etc.) and allow users to create custom categories.
- **FR1.8:** Transactions shall be tagged as **Income**, **Expense**, or **Transfer**.
### 3.4 Dashboard & History

- **FR1.9:** A home dashboard displays: Total Balance (sum of all asset accounts minus liabilities), total monthly income, total monthly expense, and a simple pie/bar chart of spending by category.
- **FR1.10:** Transaction list view with filters (date range, account, category, type) and search.

## 4. Input Form Specification – “Add Transaction”

|Field|Input Type|Required|Description|
|---|---|---|---|
|Transaction Type|Radio button|Yes|Income, Expense, Transfer|
|Amount|Numeric input (decimal)|Yes|Positive number, supports decimals|
|Date|Date picker|Yes|Defaults to today|
|Account (From)|Dropdown|Yes|Source account (list of all user accounts). For Income, this is the account receiving the money. For Expense, the account money is taken from. For Transfer, the origin account.|
|Account (To)|Dropdown|Conditional|Required only for Transfer and sometimes Income (if user wants to specify receiver account, e.g., salary to bank). For Transfer, it’s the destination account.|
|Category|Dropdown/search|Yes|Selected from predefined/user categories. For Transfer, system auto-sets “Transfer”.|
|Note|Text input|No|Optional memo|
|Recurring?|Toggle|No|If enabled, shows recurrence pattern fields (frequency, end date).|

## 5. Non-Functional Requirements

- All monetary amounts stored with 2 decimal precision in the user’s base currency.
- Transaction list lazy-loaded, supporting at least 10,000 records without performance degradation.
- Offline support for manual entry (queued sync).

## 6. Success Metrics

- 90% of active users log at least 5 transactions per month.
- Average time to add a transaction < 15 seconds.
- < 2% account balance discrepancy error reports.
